**Why test doubles:** the pages were built before the services (tasks 3.2 to 3.4). The doubles let every page and every error message be tested from the start, and the web tests stay fast and need no database. **Limit:** a passing web test shows that the page works with a service that behaves like the use case text, not that the real service does. Since 20.11 the real `AuthService` and `ProfileService` are on `main`, and the requirement tests of UC-01 to UC-03 pass with them; for the events the pages were checked on the branch of task 3.4 (#33) and again on `main` after the merge on 23.11: 36 of 36 page checks pass (section 6, item 1), and the requirement tests of UC-04 to UC-06 and UC-09 to UC-12 pass.

## 4. Test design
- **One test per rule, named as a sentence** (`test_wrong_credentials_do_not_say_which_part_is_wrong`), so a failing test says which rule is broken.
- **Main flow and alternative flows:** every use case has a test of its main flow; every alternative flow written in the use cases of this section has its own test, except the automatic expiry of UC-12, which is done by the backend (the page only shows *Rejected*). Three alternative flows (UC-04 1a, UC-10 1a, UC-11 1b) got their test while this matrix was written.
- **Boundary values:** capacity 1 and a capacity far above the facility (UC-04, BR-04); a reason of 501 characters, one over the limit (UC-12); an event at 01:00 Istanbul time, which is 22:00 of the day before in UTC; a busy slot that lasts until closing time; the one-minute wait of *Send a new code*: a second request after 20 seconds is refused, one after 80 seconds is allowed; every text at its maximum length, once with spaces and once as one word (NFR-01, found defect 14); the start time itself for *Join*, *Leave* and *Cancel* (defect 12).
- **Equivalence classes:** for *Send a new code*, unknown, verified and unverified addresses must give the same page (NFR-05); for the *Leave* redirect, five kinds of addresses (another site, `//`, another page, a backslash, empty) must all return to Find Events.
- **Negative tests for access** (NFR-04): the important pages of each role are opened with the other roles: Find Events by facility staff, Event Requests by a student and by facility staff, cancelling by a participant who is not the organizer, waiting and rejected requests by other students.
- **Coverage as a check of the tests:** the coverage run found eight error paths without a test (section 5, defect 10).
- **Performance:** 1,000 events, the number in NFR-02; each page is opened three times and the slowest time is checked, and every test first checks that the 1,000 events are really there, so a fast empty page cannot pass.
