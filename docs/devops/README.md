# CampusEvent – CI/CD and Deployment

Owner: Onur Alioğlu (tasks 3.7 CI/CD Pipeline Setup, 4.4 Deployment). Design: [Software Design Report §3.4](../software_design_report.md#34-deployment).

## Pipeline (`.github/workflows/ci.yml`)
| Job | Runs on | What it does |
|---|---|---|
| `lint` | every push, every PR to `main` | `ruff check .` (config in `pyproject.toml`) |
| `test` | every push, every PR to `main` | `python -m pytest`, uploads a JUnit report as a build artifact |
| `deploy` | push to `main` only, after `lint` and `test` pass | POSTs the Render deploy hook (`RENDER_DEPLOY_HOOK_URL` secret); skipped with a warning while the secret is not set |

Until the backend tasks (3.1–3.4) are merged, the requirement tests fail by design, so the `test` job is red and `deploy` does not run.

## Render (`render.yaml`)
Blueprint with one web service and one managed PostgreSQL 16 database (free plans).

- Build: `pip install -r requirements.txt`
- Start: `alembic upgrade head && gunicorn --chdir src "campusevent.web:create_web_app()"`: new migrations are applied before the app starts (the free plan has no shell or pre-deploy command); `alembic upgrade head` does nothing when the database is up to date.
- `autoDeploy: false` – deploys only come from the CI `deploy` job.
- `SECRET_KEY` is generated by Render, `DATABASE_URL` comes from the database, `SMTP_*` are entered in the Render dashboard.
- `create_web_app()` reads these through `campusevent.app.create_app_from_env()`: with `DATABASE_URL` users, profiles and facilities are stored in PostgreSQL; with `SMTP_HOST` the verification e-mails are sent by `SmtpEmailSender` (STARTTLS on 587, TLS on 465). Without `SMTP_HOST` the log says that no e-mails are sent, and only the verified demo users of `scripts/seed_db.py` can log in. Render's free plan blocks outgoing traffic on the SMTP ports 25, 465 and 587, so the live site runs without SMTP; see [AI mistakes caught](../ai/mistakes_caught.md#2-smtp-on-renders-free-plan).

## Live deployment (task 4.4)
**URL:** https://campusevent-86ax.onrender.com (free plan, region Oregon). Set up on 22 Nov 2026 by Harun with the checklist below.

- Blueprint `campusevent` from the public repository URL, branch `main`; it created `campusevent` (web) and `campusevent-db` (PostgreSQL 16). First deploy: `c98923c`.
- **No e-mail:** `SMTP_*` are empty on purpose. Free Render web services cannot send on ports 25, 465 and 587, and the demo does not need it: the demo users of `scripts/seed_db.py` are already verified. New sign-ups cannot verify their e-mail on the live site.
- Demo data loaded once with `scripts/seed_db.py` (External Database URL only in that one command). The demo password is kept outside the repository.
- **Limits of the free plan:** the service sleeps after 15 minutes without requests, and the first request then takes about a minute (open the site a few minutes before a demo). The free database expires 30 days after creation, on **22 Dec 2026**; after that, create a new one and run `seed_db.py` again.
- **Deploys:** `autoDeploy` is off; the CI `deploy` job calls the deploy hook only after a green build on `main`. The `RENDER_DEPLOY_HOOK_URL` secret was added to the `production` environment on 23 Nov 2026. If it is ever missing, the job is skipped with a warning; then deploy by hand: Render → `campusevent` → *Manual Deploy*.

## One-time setup checklist
1. Render: New → Blueprint → select this repository → apply `render.yaml`.
2. Render: web service → Settings → Deploy Hook → copy the URL.
3. GitHub: Settings → Environments → `production` → *Add environment secret* `RENDER_DEPLOY_HOOK_URL`.
4. GitHub: Settings → Environments → create `production` (optional: required reviewers).
5. GitHub: Settings → Branches → protect `main`: require a PR, require status checks `Lint (ruff)` and `Tests (pytest)` (turn on the test check once the backend is merged).
6. After the first deploy: open the `onrender.com` URL and check HTTPS and the login page.
7. Demo data, once per new database (the tables already exist from the start command). On your own computer, with the *External Database URL* from Render → `campusevent-db` → Connect, only for this one command (never in a committed file):
   ```bash
   DATABASE_URL="<External Database URL>" python scripts/seed_db.py
   ```
   It prints the demo accounts and their password (random unless `CAMPUSEVENT_DEMO_PASSWORD` is set); keep it for the demo. The free database expires 30 days after it is created; after creating a new one, deploy again and repeat this step.
