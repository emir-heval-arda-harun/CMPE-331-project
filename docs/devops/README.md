# CampusEvent – CI/CD and Deployment

Owner: Onur Alioğlu (tasks 3.7 CI/CD Pipeline Setup, 4.4 Deployment). Design: [Software Design Report §3.4](../software_design_report.md#34-deployment).

## Pipeline (`.github/workflows/ci.yml`)
| Job | Runs on | What it does |
|---|---|---|
| `lint` | every push, every PR to `main` | `ruff check .` (config in `pyproject.toml`) |
| `test` | every push, every PR to `main` | `python -m pytest`, uploads a JUnit report as a build artifact |
| `deploy` | push to `main` only, after `lint` and `test` pass | POSTs the Render deploy hook (`RENDER_DEPLOY_HOOK_URL` secret); skipped with a warning while the secret is not set |

Until the backend tasks (3.1–3.4) are merged, the requirement tests fail by design, so the `test` job is red and `deploy` does not run.

## Render (`render.yaml`)
Blueprint with one web service and one managed PostgreSQL 16 database (free plans).

- Build: `pip install -r requirements.txt`
- Start: `gunicorn --chdir src "campusevent.web:create_web_app()"` (Flask factory from task 3.5)
- `autoDeploy: false` – deploys only come from the CI `deploy` job.
- `SECRET_KEY` is generated by Render, `DATABASE_URL` comes from the database, `SMTP_*` are entered in the Render dashboard.
- `create_web_app()` reads these through `campusevent.app.create_app_from_env()`: with `DATABASE_URL` users, profiles and facilities are stored in PostgreSQL; with `SMTP_HOST` the verification e-mails are sent by `SmtpEmailSender` (STARTTLS on 587, TLS on 465). Without `SMTP_HOST` the log says that no e-mails are sent, and only the verified demo users of `scripts/seed_db.py` can log in. For Gmail: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, the address as `SMTP_USERNAME` and `SMTP_FROM`, and an *app password* (not the account password) as `SMTP_PASSWORD`.

## One-time setup checklist
1. Render: New → Blueprint → select this repository → apply `render.yaml`.
2. Render: web service → Settings → Deploy Hook → copy the URL.
3. GitHub: Settings → Secrets and variables → Actions → new secret `RENDER_DEPLOY_HOOK_URL`.
4. GitHub: Settings → Environments → create `production` (optional: required reviewers).
5. GitHub: Settings → Branches → protect `main`: require a PR, require status checks `Lint (ruff)` and `Tests (pytest)` (turn on the test check once the backend is merged).
6. After the first deploy: open the `onrender.com` URL and check HTTPS and the login page.
