# Non-functional tests – accounts, profiles and database (UC-01, UC-02, UC-03)

**Author:** Heval Hüseyin Demir · **Date of the results:** 20.11.2026 · **Code:** `main` with PRs #23, #24 and #25 · Part of the Software Testing Report, see the [accounts, profiles and database section](../../testing/accounts_profiles_test_section.md).

The non-functional requirements are in the [Requirements Specification](../../requirements_specification.md) (NFR-01 to NFR-07). This file lists the ones that apply to the account and profile services and the database layer. The pages of UC-01 to UC-03 (NFR-01, NFR-07) are in the [Web UI section](../../testing/web_ui_test_section.md).

| NFR | What was checked | How | Result |
|---|---|---|---|
| NFR-03 Security (salted password hashes) | Passwords and verification codes are stored only as argon2id hashes with a random salt; the same password gives different stored values; the SQL repository never returns the hash with the user | Automated: Req `test_nfr03_password_is_never_stored_in_plain_text`, `test_nfr03_same_password_gives_different_stored_values`; Unit `test_password_and_code_are_stored_only_as_argon2_hashes`; DB `test_password_hash_is_stored_but_not_returned` | ✅ |
| NFR-03 Security (HTTPS) | All traffic over HTTPS | Deployment setting, not code: Render serves the site over HTTPS. To be checked once on the deployed site (task 4.4) | ⏳ task 4.4 |
| NFR-04 Security (role-based access) | `require_role` gives `NotFoundError` for an unknown user and `PermissionDeniedError` for every other role; only students change a profile; the real check is used by `FacilityService` | Automated: Unit `test_require_role_refuses_every_other_role`, `test_require_role_rejects_an_unknown_user`, `test_only_students_can_change_a_profile`, `test_facility_service_uses_the_real_role_check`; DB `test_require_role_with_sql_repository` | ✅ |
| Security of log in and sessions (UC-02 2a, BR-03; design report 3.2) | An unknown e-mail and a wrong password give the same message, and the unknown case also hashes a password so the time does not tell; the account is named as unverified only after a correct password; the session token is signed with HMAC-SHA256, compared in constant time and valid 24 h; codes come from `secrets`, are valid 15 minutes and once | Automated: Unit `test_unknown_email_and_wrong_password_give_the_same_message`, `test_unverified_user_with_wrong_password_is_not_told_that_the_account_exists`, `test_changed_or_made_up_tokens_are_rejected`, `test_token_of_another_secret_key_is_rejected`, `test_token_expires_after_the_session_lifetime`, `test_code_does_not_work_after_15_minutes`, `test_new_code_replaces_the_old_one`; timing: code review of `login` | ✅ No limit on wrong code attempts yet (see limits in the section) |
| NFR-05 Privacy | No e-mail address or password hash leaves the account part: `SqlUserRepository` returns `User` objects without the hash; `resend_code` does not say whether an address is registered or verified | Automated: DB `test_password_hash_is_stored_but_not_returned`; Unit `test_new_code_is_not_sent_to_unknown_or_verified_addresses` | ✅ |
| NFR-06 Maintainability | All tests of this section run with one command (`python -m pytest`); the database tests are skipped without `TEST_DATABASE_URL` instead of failing; the tests never read `DATABASE_URL` from the environment, so they cannot write to a real database | `python -m pytest` (CI on every pull request); Unit `test_from_env_without_settings_keeps_data_and_mails_in_memory`; coverage in the [coverage file](../coverage/accounts-profiles.md#code-coverage) | ✅ 78 unit, 52 database and 12 requirement tests, 0 failures |
| Reliability (design report 7.1) | One transaction per request; a refused change leaves nothing behind; after a constraint error the session is usable again; each request thread has its own session, closed after the request | Automated on PostgreSQL 16: UoW `test_rollback_stores_nothing`, `test_after_a_constraint_error_rollback_makes_the_session_usable_again`, `test_each_request_thread_gets_its_own_session`; Wire `test_database_session_is_closed_after_every_request`; Unit `test_invalid_change_keeps_the_saved_profile`, `test_rejected_input_stores_nothing_and_sends_nothing` | ✅ |
| Data integrity (design report §6) | The database itself refuses invalid rows even if a service had a bug: duplicate e-mail in any case, unknown role, interests not trimmed or not lower case, overlapping active events or blocks | Automated on PostgreSQL 16: the 31 tests in `tests/db/test_schema.py` | ✅ |
| Availability of e-mail (design report 3.2) | A mail server problem does not crash sign-up: it becomes `EmailDeliveryError` and the page shows a message with status 503 | Automated with a stand-in SMTP server: Wire `test_mail_server_problems_become_email_delivery_error`, `test_mail_server_problem_is_shown_on_the_sign_up_page` | ✅ Real delivery on Render (Brevo, port 2525) is checked in task 4.4 |

**Not applicable here:** NFR-02 (search speed) is about event search (UC-05). NFR-01 and NFR-07 are about the pages, see the Web UI section.
